# Собственный движок

Актуальный контракт 0.7.1 расширяет генерацию до 36 стран. См. [country-expansion.md](country-expansion.md). Первоначальные три страны и их релиз сохранены для старых жизней.

Контракт 0.7.0, движок childhood-2. Реализованы расширенная карточка рождения, детство, повторяемые решения, последствия, семья и динамическая смертность. Подробности изменений и задания frontend — [birth-and-life-v2.md](birth-and-life-v2.md), источники — [statistical-sources.md](statistical-sources.md). Полная модель карьеры и взрослых сюжетов ещё не готова. Старый `LocalLifeEngine`, `/advance` и `1in8b` сохранены. Frontend не изменялся.

## Данные

В PostgreSQL импортируются 12 наблюдений WDI за 2023 год: Россия, Индия, Япония × население, коэффициент рождаемости, отношение мальчиков к девочкам при рождении, доля городского населения. Источник обновлён 2026-11-11. Снимок и SHA-256 находятся в `src/main/resources/statistics/`. Лицензия CC BY 4.0, атрибуция: World Bank, World Development Indicators; первичные источники указаны в метаданных показателей. Это опубликованные оценки, не индивидуальные записи людей.

- [Население](https://databank.worldbank.org/metadataglossary/world-development-indicators/series/SP.POP.TOTL)
- [Рождаемость](https://databank.worldbank.org/metadataglossary/world-development-indicators/series/SP.DYN.CBRT.IN)
- [Соотношение полов](https://databank.worldbank.org/metadataglossary/world-development-indicators/series/SP.POP.BRTH.MF)
- [Урбанизация](https://databank.worldbank.org/metadataglossary/world-development-indicators/series/SP.URB.TOTL.IN.ZS)
- [Лицензии World Bank](https://datacatalog.worldbank.org/public-licenses)

В childhood-2 вес страны берётся из числа рождений UN WPP 2024, прогноз 2026, а не из прежнего произведения населения и коэффициента рождаемости. Новая миграция V5 и импорт добавляют 3 профиля стран и 46 662 строки смертности. Вероятность мужского пола = ratio / (1 + ratio), доля городского населения приближает долю городских рождений; эти два показателя пока из WDI 2023. Год и происхождение остальных величин указаны в birthFacts.

Имена, два родителя, 0–3 старших ребёнка, возраст родителей, профессии, достаток, жильё и начальные характеристики — явно игровые допущения. Вера семьи выбирается по долям населения Pew 2020, язык — приближённо по весам CLDR 48; это не обследование семей новорождённых. Электричество и собственность на жильё остаются null. Мать 22–35 лет, отец старше на 0–5 лет — параметры игровой модели. `birthDetails` и `birthFacts` остаются снимком рождения; актуальная семья — `simulation.family`.

## Импорт и проверка

Из каталога backend в PowerShell, при работающем Docker Desktop:

```powershell
docker compose build backend
docker compose run --rm --no-deps backend --spring.main.web-application-type=none --life.statistics.import=true
docker compose up -d --no-deps --wait backend
docker compose exec -T postgres psql -U life_app -d life_db -c "select release_id, country_iso3, count(*) from statistical_observation group by release_id, country_iso3 order by country_iso3;"
```

Импорт использует уже скачанный снимок; при старте игры внешней сети не требуется. Проверяются checksum, дата обновления, полнота, уникальность, единицы и диапазоны. Повторный импорт не создаёт дубли. При отсутствии данных новая генерация отвечает `503 STATISTICS_NOT_READY`. Миграция V4 создаёт таблицы и nullable JSONB `life_session.simulation`; V1–V3 не меняются. Скрипт `scripts/download-birth-statistics.ps1` скачивает новый кандидат в отдельную папку. Обновления публикуются осознанно вместе с новой версией данных, существующий снимок не перезаписывается.

## Подключение frontend

1. Существующий `POST /api/v1/guest`, затем `POST /api/v1/sessions/generated/local` с `{}` либо `{"countryIso3":"RUS","birthYear":2026}`. Заголовок `Idempotency-Key` — UUID. Повтор создания с тем же ключом и эквивалентными параметрами возвращает ту же жизнь. Коды входа ISO3, а `character.birthplace.countryCode` остаётся ISO2.
2. Сохранить id. «Начать жизнь» открывает эту сессию, не создаёт вторую. Существующий `/generated` по-прежнему вызывает 1in8b.
3. Расширить типы и декодеры необязательным nullable `simulation` по OpenAPI. Для новых жизней `provider=local`, `simulation.engineVersion=childhood-2`. При `simulation=null` продолжать прежний сценарий `/advance`.
4. Для новой жизни выполнять `POST /{id}/step` с `{"expectedVersion":N}` каждые два игровых месяца: 10 секунд на 1× при годе 60 секунд. Скорость применяется к анимации. Запросы не отправляются на каждый кадр. Блокировать время на запросе, ошибке, решении и окне покупки.
5. Ответ — новый полный снимок Session. Показывать новые события сразу: они уже произошли. Не пропускать их через старый механизм задержки на целый год. Покупка и ответ на решение не сбрасывают прогресс: ключ часов должен учитывать `id` и `simulation.elapsedMonths`, а не общий `version` или id решения.
6. Выбор отправляется существующим `/decisions/{decisionId}/answers`. Он сохраняет последствия, но не продвигает месяц. Следующий `/step` проверяет новое состояние. До возраста трёх лет решений нет.
7. При F5 выполнить GET той же Session. Начальный прогресс года = `simulation.monthOfYear / 12`. Уже завершённые шаги сохранены. Неподтверждённая анимация внутри текущего двухмесячного интервала пока не сохраняется; отдельного `/playback` на этом этапе нет.
8. Семью показывать из `simulation.family`, навыки — из `simulation.skills`. Возраст родственников актуальный; `birthDetails` содержит возраст при рождении. ID родственника устойчив внутри сессии. Скрытые флаги и очередь будущих событий не отправляются клиенту.
9. Покупки, финансы, редактирование и ошибки версий используют существующие маршруты. Новые коды: `STEP_REQUIRED`, `STEP_UNSUPPORTED`, `STATISTICS_NOT_READY`, `CONTENT_UNAVAILABLE`, `ENGINE_VERSION_UNAVAILABLE`.

Последний шаг года увеличивает `state.age`, но запись относится к только что прожитому году. Шесть шагов дают шесть событий, ответы иногда добавляют дополнительные записи. На нулевом году дополнительно присутствует рождение. Стабильные id записей позволяют избежать повторного показа.

## Причинность и экономика

Каталог `events/childhood-2.json` содержит 97 ситуаций с условиями по возрасту, среде, навыку, флагам, живому участнику и близости; cooldown и одноразовые события. Выбор рисования или конструктора создаёт разные навыки и разные последующие события. Помощь родителю меняет близость и доверие, открывает отложенное доверенное дело. Моральные решения меняют ауру. Отложенные события снова проверяют условия перед применением. Случайный выбор воспроизводим по seed и месяцу. Childhood-1 поддерживается для продолжения старых сохранений, без перегенерации прошлого.

Все операции проходят через прежнюю блокировку сессии, проверку владельца, expectedVersion и журнал ключей. В той же транзакции сохраняются мир, решение, история и бюджет. Новые local используют помесячный расчёт существующего бюджета; старые local сохраняют прежний годовой. В новой модели проценты 1% номинальных годовых начисляются по месяцам на положительный начальный остаток, с округлением до копеек. Доходы пока остаются возрастной игровой моделью; карьера и семейные счета будут отдельным этапом. Разделения денег на депозит и кошелёк пока нет.

Возрастного предела в семь лет нет. Жизнь завершается динамически по таблицам смертности ООН; родственники также могут умереть. Контент после детства пока базовый; полноценные подростковые/взрослые модели, болезни и причины смерти, разнообразные типы семей, долговременный жизненный цикл питомцев, точные календарные даты и сохранение анимации между шагами ещё не реализованы. Питомцы пока остаются покупками существующей экономики.

## Проверки

Ручная проверка на Windows (PowerShell в каталоге backend):

```powershell
.\scripts\Test-LocalLife.ps1
```

Она создаёт отдельного гостя и новую тестовую жизнь, проходит до семи лет и проверяет повтор шагов. Параметр `-Country JPN` или `-Country IND` выбирает другую страну. `-RestartBackend` дополнительно перезапускает backend один раз посреди решения и проверяет восстановление. Перезапуск кратковременно прерывает обслуживание frontend; обычная проверка обходится без него.

Проверено 24.11.2026 для 0.7.0: Maven — 22 теста без ошибок и пропусков, включая OpenAPI, сохранение бонусов покупок, 100 seed без повторов шаблонов внутри года, последствия и динамическую смерть. На реальной тестовой PostgreSQL проверены три страны и 12 жизней до завершения, формула qx и открытый возраст 100+. Резервные копии рабочих данных сохраняются в игнорируемой `target/backups/`. Проверки создают отдельные тестовые сохранения.

Unit-тесты проверяют 100 seed, воспроизводимость, возраст решений, шесть шагов в год, причинные ветки, продолжение после семи лет и независимость бюджета от размера шага. Integration-тест проходит все три страны, повтор импорта/создания/шага/ответа/покупки, конфликт версий, восстановление каждого шага и покупку питомца. Прежние тесты сессий и 1in8b остаются обязательными. Внешний API в автоматических тестах подменён.

# Имена и фамилии новых персонажей

Модель `country-names-1`, 26.11.2026. Действует только в новых сгенерированных локальных жизнях. Frontend и форма API 0.9.1 не меняются: полное имя возвращается в `character.name`, `simulation.family[].name`, подписях родителей и списке сохранений. Не нужно разбивать эти строки по пробелам.

## Данные и ограничения

`src/main/resources/names/country-names-1.json` содержит **36 стран и 292 варианта семейных компонентов** с явно заданными мужскими/женскими формами. Это вручную составленный игровой справочник русских записей имён, не импорт статистики, не список реальных людей и не таблица распространённости фамилий. Варианты выбираются равномерно; пол, достаток, религия и профессия не выводятся из фамилии. Имена по-прежнему берутся из существующего `country-catalog.json`.

Справочник охватывает отдельные варианты именования, а не все языковые и этнические группы страны. Например, для Индии выбран вариант с наследуемой фамилией, для Индонезии — примеры семейных имён; это не означает, что каждый житель этих стран имеет фамилию. У малайзийского и эфиопского вариантов вторая часть — имя отца, а не неизменная фамилия рода. Все сгенерированные имена имеют как минимум две части по запросу игры; пользовательские имена из одного слова остаются допустимыми.

Правила учитывают различия порядка, форм и наследования, описанные в [W3C — Personal names around the world](https://www.w3.org/International/questions/qa-personal-names). Эфиопский вариант проверен по [HM Passport Office — Ethiopia](https://www.gov.uk/government/publications/ethiopia-knowledge-base-profile/ethiopia-knowledge-base-profile), сохранение корейских фамилий — по [Ministry of Culture, Sports and Tourism](https://www.mcst.go.kr/english/policy/kocis/newsView.jsp?pSeq=88). Источники использованы для проверки принципов; массовые наборы персональных данных не скачивались. Применённые игровые правила не воспроизводят полностью обычаи или законодательство стран.

## Правила генерации

- В России, Казахстане и Узбекистане используются явные пары форм, например `Иванов/Иванова`, без угадывания окончания произвольной строки. Ребёнок и братья/сёстры получают общий семейный компонент.
- В Японии, Китае, Южной Корее и Вьетнаме семейная часть выводится перед личным именем. В китайском, корейском и вьетнамском вариантах родители генерируются со своими фамилиями.
- Для Мексики, Аргентины, Колумбии, Перу и Чили выбран вариант из двух фамилий: первая от отца, затем первая от матери. Для Бразилии — материнский и отцовский компоненты в таком порядке; в этой двухчастной игровой модели наследуется последняя часть имени соответствующего родителя.
- В Эфиопии и Малайзии ребёнок получает личное имя отца вторым компонентом. При отсутствии известных данных берётся сохранённый игровой вариант из справочника; вымышленный родственник не добавляется в семью. Частицы и многоступенчатые цепочки предков здесь не моделируются.
- В остальных случаях используется один семейный компонент. В режиме `SHARED` родители при рождении имеют общий компонент, в `SEPARATE` — независимые. Это правила конкретного набора, а не утверждение обо всех семьях страны. При одном известном родителе наследуемая фамилия берётся у него. В двухчастном варианте неизвестная линия выбирается из справочника и затем сохраняется; братья и сёстры используют ту же комбинацию.

Новые партнёры, друзья и родственники во взрослой жизни получают имена по стране текущего проживания. Для детей, внуков и правнуков используются сохранённые компоненты имён известных родителей; семейные связи определяются по ID, не по совпадению строк. Существующие партнёры не переименовываются автоматически при браке, разводе или переезде. Для усыновления в игре применяется то же правило имени ребёнка в семье.

## Сохранения и настройки

В серверном `simulation.naming` сохраняются версия модели и компоненты созданных имён по ID, включая `character`. Эти данные не добавлены в публичный DTO. `LocalSimulation.evolve`, обновление контекста рождения и ручные настройки сохраняют модель. Полные отображаемые строки также остаются в прежних полях.

**Отсутствие `naming` означает прежний алгоритм.** Старые жизни не получают фамилии при чтении, продолжении, настройке персонажа или появлении новых NPC. Исходные имена, родственники и тексты истории не переписываются. Внешний `1in8b` и ручное создание через прежний `POST /sessions` не подключаются к новому генератору.

Выбор фамилий использует отдельные воспроизводимые случайные последовательности. Он не сдвигает выбор страны, состава семьи, личных имён, характеристик, черт NPC или дальнейших событий. Повторное создание по прежнему `Idempotency-Key` возвращает уже сохранённую жизнь.

При ручной замене имени оно сохраняется буквально. Старые структурные компоненты этого человека удаляются из `naming`, чтобы дети не наследовали фамилию, которую игрок уже заменил. Пользовательская строка не разбирается на предполагаемые имя и фамилию: для последующих детей используется другой известный родитель либо вариант из справочника. Удалённые/заменённые родственники и изменения пола при настройке обрабатываются аналогично. Изменение страны не переименовывает существующих людей.

Новая миграция Flyway не требуется: поле необязательно и находится внутри существующего JSONB. Существующие миграции не редактировались. Справочник не загружает статистические таблицы PostgreSQL: выбранные имена и их компоненты сохраняются вместе с новой жизнью. Для будущей смены правил нужен новый номер модели; `country-names-1` должен оставаться воспроизводимым.

## Файлы

- `engine/names/NameCatalog.java`, `NamingState.java`, `PersonalNames.java` — справочник, сохранённые компоненты и генератор.
- `resources/names/country-names-1.json` — 36 стран и варианты.
- `statistics/CountryCatalog.java` — загрузка и проверка полного покрытия.
- `engine/local/CharacterGenerator.java`, `LocalSimulation.java`, `engine/adult/AdultWorld.java` — рождение и новые родственники.
- `session/BirthCustomizationService.java`, `LifeSession.java` — совместимость ручного редактирования.
- `PersonalNamesTest.java`, `AdultNamingTest.java`, дополнения `BirthEconomyIntegrationTest.java`, `LocalSimulationIntegrationTest.java`, `CharacterCustomizationIntegrationTest.java` — генерация, наследование, сохранения и API.
- `CountryExpansionIntegrationTest.java` — проверка личного имени внутри нового полного имени; `AdultSessionIntegrationTest.java` — устранение случайного ожидания непустого слайд-шоу через явное значимое решение в тестовой жизни.
- `docs/openapi.yaml`, `docs/integration.md`, `docs/event-presentation.md`, этот документ — актуальное описание полей и правил.

Для ручной проверки создайте **новую локальную жизнь**. В карточке и списке родных должны быть полные имена. Обновите страницу: имена должны остаться прежними. Откройте старое сохранение: его имена не должны измениться. Frontend использует существующее поле `name`, доработка подключения не требуется.

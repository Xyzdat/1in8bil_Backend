# Интеграция игрового экрана

## Доходы и расходы — контракт 0.11.0

Добавлены GET `/api/v1/sessions/{sessionId}/budget/{section}` для `income`, `expenses`, `jobs`, `side-jobs`, `businesses`, `strategies`, `assets`; предпросмотр продажи `/budget/assets/{assetId}/sale-preview`; команды POST `/budget/actions`. Все изменения используют прежние cookie, expectedVersion и Idempotency-Key. Ответ команды — полный Session с nullable `budgetAction` (APPLIED/DECLINED); отказ не меняет версию жизни. Пока ожидается сюжетный выбор, финансовые изменения заблокированы. В операциях добавлены sourceId/categoryId/relatedId, приобретения могут иметь статус SOLD. Прежние маршруты покупок сохраняются. Frontend не изменён. Контракт, примеры, ограничения и порядок подключения: [budget-management.md](budget-management.md).

## Фокус года — контракт 0.10.0

Новые локальные жизни возвращают `simulation.yearlyFocus`: текущий выбор, доступные направления, контекст и положительные/отрицательные темпы характеристик, навыков и близости за 12 месяцев. Изменение через `PATCH /api/v1/sessions/{sessionId}/focus` с `expectedVersion`, `focusId` и `Idempotency-Key`. Выбор не двигает время и не начисляет бонус; эффекты накапливаются на шагах. Фокус влияет на веса новых событий и цепочек, сохраняя условия и предел вопросов. Старые жизни не подключаются автоматически. Frontend не менялся; для подключения нужны типы/декодеры и обработчик выбора без моковых начислений. Подробности и пример запроса: [year-focus.md](year-focus.md).

## Конкретные профессии родителей — формат API 0.9.1 сохранён

Новые рождения `birth-economy-2` возвращают конкретное занятие с пометкой `· игровая специализация` в прежних `birthDetails.mother/father.occupation.label`, `background.mother/father` и `simulation.family[].occupation`. Код остаётся статистической группой ISCO. Китай использует отдельный набор модельных оценок ILO до 2025 года, с сохранением объединённой группы 6+9. Никаких дополнительных запросов или пересчётов на frontend не требуется; отображать строку полностью. Старые жизни не пересчитываются. Методика и оговорки: [parent-occupations.md](parent-occupations.md).

## Фамилии новых персонажей — формат API 0.9.1 сохранён

Новые локальные жизни используют `country-names-1`: персонаж, родители, братья/сёстры и новые родственники получают полные имена с учётом страны и семейных связей. Они приходят в прежних `character.name`, `simulation.family[].name` и подписях родителей. Не разбивать имя по пробелу: возможны фамилия перед личным именем и несколько семейных компонентов. Старые сохранения не переименовываются. Frontend менять не требуется. Справочник, наследование и ограничения: [country-names.md](country-names.md).

## Важность событий и последствия вариантов — контракт 0.9.1

Добавлены nullable-поля `state.history[].importance` (0–100), `importanceSource` и `state.pendingDecision.options[].effects` с непосредственными изменениями `stats` и близости `closeness` по ID родственника. Важность связанных событий пересматривается вместе с сохранённой историей решений, поэтому нужно обновлять всю летопись из ответа. Предпросмотр не прибавлять к состоянию самостоятельно. `null` означает неизвестные эффекты, пустые карты — отсутствие непосредственных изменений этих показателей. `character.name` и имена родных выводить целиком. Frontend не изменён. Формат, ограничения, пример и задание без изменения вёрстки: [event-presentation.md](event-presentation.md).

Старые сохранения не пересчитываются, frontend менять не требуется. Формулы, покрытие и допущения — [birth-economy.md](birth-economy.md).

## Запуск и проверка

Для контейнерного запуска и отладки Java с базой в Docker см. [Docker Compose и VS Code](docker.md).

В терминале backend задайте `DB_PASSWORD` для текущего процесса PowerShell, если переменной ещё нет. В Windows PowerShell можно ввести пароль интерактивно.

```powershell
$lifeCredential = Get-Credential -UserName life_app -Message 'Пароль PostgreSQL для life_app'
$env:DB_PASSWORD = $lifeCredential.GetNetworkCredential().Password
Remove-Variable lifeCredential
.\mvnw.cmd spring-boot:run
```

При запуске Flyway применяет миграцию `V1`, затем Hibernate сверяет таблицы с Java-моделями. Проверка HTTP в другом терминале должна вывести `UP`.

```powershell
Invoke-RestMethod http://localhost:8080/api/v1/health
```

Тест HTTP без базы запускается командой `.\mvnw.cmd '-Dtest=HealthControllerTest' test`. Для полного теста заведите отдельную базу PostgreSQL и укажите её в `LIFE_TEST_DB_URL`. Тесты применяют миграции и записывают данные в эту базу. `LIFE_TEST_DB_USERNAME` по умолчанию равен `life_test`. При необходимости передайте пароль через `LIFE_TEST_DB_PASSWORD` тем же способом. Затем запустите `.\mvnw.cmd test`.

## Жизненный цикл сохранения

1. Вызвать `POST /api/v1/guest` с JSON `{}` и дождаться ответа перед запросами сохранений. Браузер хранит cookie `life_owner` до года и отправляет её автоматически. Для frontend используйте относительные адреса `/api/v1/…` в том же origin, например через прокси Vite в разработке. Для HTTPS укажите `LIFE_GUEST_SECURE_COOKIE=true`.
2. Вызвать `POST /api/v1/sessions` по явному действию «Начать жизнь». Сопоставить данные из `App.jsx` с `character` и `startingStats`. В `birthplace.countryCode` передавать двухбуквенный код из каталога frontend. Сохранить полученный `id` как идентификатор активной жизни. Если ответ потерялся, повторить запрос с тем же ключом.
3. При входе в игровой экран или после обновления страницы вызвать `GET /api/v1/sessions/{id}`. `GET /api/v1/sessions` показывает доступные сохранения, если активный идентификатор потерян. Гостевой доступ привязан к cookie браузера. Для переноса сохранений между устройствами понадобится учётная запись.
4. Отрисовывать прогресс года локально по 60 секунд на 1×, с паузой и скоростями из текущего интерфейса. На границе года отправить один `POST /api/v1/sessions/{id}/advance`. В этой версии возраст хранится целым числом, а дробный прогресс, пауза и скорость относятся к UI. После загрузки прогресс начинается с сохранённой границы года.
5. При наличии `state.pendingDecision` остановить переход года и отправить выбранный `optionId` в `POST /api/v1/sessions/{id}/decisions/{decisionId}/answers`. Обновить экран по ответу backend. Каждая принятая команда сразу сохраняет состояние и летопись. При `state.status = COMPLETE` остановить таймер.

Для каждой новой команды создавайте новый UUID в заголовке `Idempotency-Key`. Тот же ключ и то же тело повторно читают актуальную версию сохранения без второго применения команды. Ключ создания действует в пределах гостя, ключ ответа или перехода года действует в пределах сохранения. `expectedVersion` берите из последнего ответа. При `VERSION_CONFLICT` заново загрузите состояние через GET. `IDEMPOTENCY_CONFLICT` означает, что ключ уже использовался с другими параметрами. Другие ошибки состояния имеют коды `DECISION_REQUIRED`, `DECISION_CHANGED` и `SESSION_COMPLETE`. Невалидные данные возвращают `INVALID_REQUEST` или `INVALID_OPTION`. Чужое сохранение даёт тот же ответ `404 SESSION_NOT_FOUND`, что и отсутствующее.

Для ручной проверки создайте жизнь и дойдите до решения в три года. После ответа можно перезапустить backend, сохранив этот терминал с переменными, и выполнить последние две команды.

```powershell
$lifeApi = 'http://localhost:8080/api/v1'
Invoke-RestMethod "$lifeApi/guest" -Method Post -ContentType 'application/json' -Body '{}' -SessionVariable lifeBrowser

function Send-LifeAction($path, $payload) {
    Invoke-RestMethod "$lifeApi/$path" -Method Post -WebSession $lifeBrowser `
        -ContentType 'application/json; charset=utf-8' `
        -Headers @{ 'Idempotency-Key' = [guid]::NewGuid().ToString() } `
        -Body ($payload | ConvertTo-Json -Depth 6 -Compress)
}

$lifeSave = Send-LifeAction 'sessions' @{
    character = @{
        name = 'Алекс'
        gender = 'Мужчина'
        birthYear = 2026
        birthplace = @{ countryCode = 'CA'; country = 'Канада'; city = 'Оттава' }
    }
    startingStats = @{ health = 91; intelligence = 72; appearance = 64 }
}
$lifePath = "sessions/$($lifeSave.id)"
foreach ($lifeYear in 1..3) {
    $lifeSave = Send-LifeAction "$lifePath/advance" @{ expectedVersion = $lifeSave.version }
}
$lifeDecision = $lifeSave.state.pendingDecision
$lifeSave = Send-LifeAction "$lifePath/decisions/$($lifeDecision.id)/answers" @{
    expectedVersion = $lifeSave.version
    optionId = 'build'
}

$lifeSave = Invoke-RestMethod "$lifeApi/$lifePath" -WebSession $lifeBrowser
$lifeSave = Send-LifeAction "$lifePath/advance" @{ expectedVersion = $lifeSave.version }
```

Итоговое сохранение имеет тот же `id`, возраст 4, версию 6 и два события в летописи. Интеллект увеличивается с 72 до 75.

## 1in8b Engine

Владелец проекта подтвердил разрешение на использование ключа. При показе сгенерированной жизни укажите источник «1in8b Engine (1in8b.life)» со ссылкой и отметьте, что жизнь смоделирована. Для публичного выпуска учитывайте объём полученного разрешения и условия провайдера. [Условия API](https://1in8b.life/en/api/#terms-of-use)

### Запуск с ключом

В Docker ключ берётся из локального `.env` backend по имени `LIFE_1IN8B_API_KEY` или `API_KEY`. Compose передаёт его в сервис `backend`. При запуске Java из VS Code передайте ту же переменную в окружении процесса, например через `.env.vscode`. Для шифрования токенов жизни можно задать отдельный постоянный секрет `LIFE_1IN8B_TOKEN_SECRET`. Если он пуст, для шифрования используется ключ API. В таком режиме замена ключа сделает ранее сохранённые токены недоступными. Для независимой ротации ключа задайте отдельный секрет до первой генерации и сохраняйте его при развёртываниях.

### Подключение в frontend

1. На явное действие «Играть» вызовите `POST /api/v1/guest`, затем `POST /api/v1/sessions/generated` с JSON `{}` и `Idempotency-Key`. Ответ содержит `provider: "1in8b"`, `id`, анкету и состояние. Сохраните `id` активной жизни и покажите данные рождения из `character`.
2. Нажатие «Начать жизнь» открывает этот же `id`. При повторной загрузке вызовите `GET /api/v1/sessions/{id}`. Backend берёт сохранение из PostgreSQL. Для серверного сценария с ручной анкетой остаётся `POST /api/v1/sessions` с `provider: "local"` в ответе.
3. Новая жизнь начинается с `state.age = 0` и `pendingDecision = null`. Таймер запускается при открытии игрового экрана. Показывайте фактический возраст из ответа. При `pendingDecision = null` используйте `advance`, чтобы дойти до следующего дня рождения или ожидающего решения. При решении отправьте его `id` и `optionId`. Ответ на решение может перейти к следующему дню рождения. После каждой принятой команды заменяйте снимок ответом backend и берите из него историю и версию. При `COMPLETE` остановите игру. Жизнь поставщика может завершиться до или после 22 лет.
4. Декодер состояния должен принимать `null` для `stats.appearance` и `stats.aura`. Внешность можно задать через редактирование анкеты, аура отсутствует у 1in8b. `stats.intelligence` и `stats.relationships` соответствуют общим `knowledge` и `bonds` из ответа провайдера. Для сохранений обоих движков применяются одинаковые правила версий и повторов команды.

### Карточка рождения

Новые жизни 1in8b возвращают `character.birthDetails` в полном ответе о сессии. Это снимок при рождении. Он сохраняется при загрузке, переходах по годам и изменении имени. Для старых сохранений и ручных анкет блок равен `null`. При обращении к старой версии backend поле может отсутствовать.

- `placeType` сообщает тип местности, `URBAN` — городская, `RURAL` — сельская. Поле может быть задано, даже когда `character.birthplace.city` пусто.
- `mother` и `father` содержат `age`, `occupation`, `alive` и `livesWithChild`. `occupation` содержит `code` и русскую подпись `label`. `background.mother` и `background.father` тоже содержат подписи, когда они известны. Для перевода backend использует публичный справочник профессий с часовым кэшем. Если справочник недоступен или кода в нём нет, возраст и код профессии остаются доступны, а подпись равна `null`.
- `familyType`, `olderSiblingCount`, `familyIncomeQuintile`, `fatherPresent`, `siblings` и `household` описывают семью и домохозяйство. Строковые подписи о семье и достатке также доступны в `background`.
- `homeOwned` и `electricityAtHome` описывают условия дома. Для `homeOwned: false` можно показать «Нет собственного жилья». Условия аренды неизвестны.
- `faithCode`, `group`, `caste` и `disabilityCodes` заполняются, когда 1in8b возвращает эти сведения. У `group` и `caste` есть `code` и отображаемое `name`, если оно доступно. Религия по-русски доступна в `background.religion`.

Все эти поля показываются для чтения. Для отсутствующих данных пропускайте строку или показывайте «Нет данных». Учитывайте `false`, `0` и пустой список как полученные значения. Статистика страны и точный тип жилья не входят в ответ о новорождённом.

### Редактирование созданного персонажа

`PATCH /api/v1/sessions/{id}/character` принимает `expectedVersion`, объект `changes` и заголовок `Idempotency-Key`. Cookie гостя и проверка версии действуют так же, как для перехода года. В ответе приходит полный снимок той же сессии с новой версией. Замена отображаемого имени применяется к игровому экрану и списку сохранений. Уже записанные события летописи хранят исходный текст.

- Для `1in8b` разрешены `changes.name` и `changes.stats.appearance`. Внешность хранится как значение приложения и сохраняется после хода. Попытка изменить здоровье или интеллект вернёт `409 CHARACTER_FIELDS_READ_ONLY`. Другие поля анкеты отображаются для чтения.
- Для `local` также редактируются `changes.stats.health` и `changes.stats.intelligence`. Оценки задаются целыми числами от 0 до 100. Отправляйте только изменённые поля.

Для подключения редактора во frontend используйте `provider`, чтобы включить поддерживаемые поля. Внешность должна быть доступна для ввода и при исходном `null`. При сохранении отправляйте PATCH, применяйте полученный снимок и оставляйте тот же `sessionId`. При `VERSION_CONFLICT` загрузите свежую сессию. При сетевой ошибке повторите ту же подготовленную команду.

Для ручной проверки Docker вместо создания по анкете в сценарии выше используйте следующий фрагмент. Создание и каждое принятое действие расходуют квоту поставщика.

```powershell
$lifeApi = 'http://127.0.0.1:8081/api/v1'
Invoke-RestMethod "$lifeApi/guest" -Method Post -ContentType 'application/json' -Body '{}' -SessionVariable lifeBrowser
$lifeSave = Invoke-RestMethod "$lifeApi/sessions/generated" -Method Post -WebSession $lifeBrowser `
    -Headers @{ 'Idempotency-Key' = [guid]::NewGuid().ToString() } -ContentType 'application/json' -Body '{}'
$lifeSave | Select-Object id, provider, version, @{n='Age';e={$_.state.age}}
$lifeSave.character.birthDetails | ConvertTo-Json -Depth 8
$lifeSave.state.history
$lifeEdit = @{ expectedVersion = $lifeSave.version; changes = @{ name = 'Лина'; stats = @{ appearance = 84 } } }
$lifeSave = Invoke-RestMethod "$lifeApi/sessions/$($lifeSave.id)/character" -Method Patch -WebSession $lifeBrowser `
    -Headers @{ 'Idempotency-Key' = [guid]::NewGuid().ToString() } -ContentType 'application/json; charset=utf-8' `
    -Body ($lifeEdit | ConvertTo-Json -Depth 4 -Compress)
```

В ответе на создание ожидается `Age = 0`. Первый переход проверяется отправкой `POST /api/v1/sessions/{id}/advance` с `expectedVersion` из ответа и новым ключом команды. Старые сохранения продолжаются с того возраста, который в них записан.

Автоматические тесты используют подменённые ответы поставщика. Для восстановления и анимации времени используются сохранённые данные приложения.

| Механика frontend | Что подтверждает публичная документация |
| --- | --- |
| Возраст и решения | `GET /person?age=0&token=1` возвращает состояние новорождённого и токен. Затем `POST /live` с `until: "year"` продвигает эту же жизнь до следующего дня рождения или решения. |
| Характеристики и фокус | Есть здоровье, счастье, `knowledge`, общий показатель `bonds` и варианты фокуса. Соответствие шкалам интеллекта и отношений, а также вариантам фокуса приложения требует проверки. |
| Аура и внешность | В описании состояния нет показателей ауры и внешности. Поддержку услуг и их эффекты для внешности нужно проверить. |
| Близость с каждым родственником | Описаны состав семьи и общий `bonds`. Индивидуальные шкалы близости и характеристики друзей не подтверждены. |
| Покупки | `sheet` показывает позиции с ценами в PPP-долларах. Backend сохраняет предложения при обычном ходе и отдаёт их для чтения. Параметр `buy` поставщика привязан к ходу и пока не подключён. |
| Детализация расходов | Backend сохраняет доход и чистую стоимость имущества из состояния 1in8b. Расходы, доступный остаток и журнал для этого поставщика возвращаются как `null`. |

Для страны рождения используется распределение поставщика для `/person`. Документация отличает его от распределения рождений при запуске через `/live`. Сведения о состоянии, покупках и токене приведены в разделах People alive now и A life lived from outside. [Документация API](https://1in8b.life/en/api/)

Внешний HTTP-клиент находится внутри адаптера `LifeEngine`. Сохранение закрепляется за движком, который его создал. Финансовые ответы содержат валюту `RUB` или `PPP_USD`.

Документация Free указывает 30 вызовов в минуту и 2 000 единиц в месяц на ключ. Адаптер ограничивает вызовы до 30 в минуту на экземпляр приложения. При отказе поставщика он возвращает код `ENGINE_RATE_LIMIT`, `ENGINE_QUOTA_EXCEEDED`, `ENGINE_KEY_REJECTED`, `ENGINE_CURSOR_REJECTED`, `ENGINE_INVALID_RESPONSE` или `ENGINE_UNAVAILABLE`. Для повторного создания backend использует seed, полученный из владельца и ключа команды. Уже сохранённая команда возвращает сохранение из базы. Если первый ответ поставщика потерян, повтор может снова потратить квоту, а тот же seed воспроизводит жизнь только в той же версии движка. [Лимиты API](https://1in8b.life/en/api/#limits)

API описывает срок токена `/live` в 90 дней с начала жизни. Backend хранит токен в PostgreSQL в зашифрованном виде и сохраняет исходный срок при каждом шаге. При истёкшем токене летопись доступна, новые действия возвращают `ENGINE_TOKEN_EXPIRED`. Если конфигурация шифрования изменилась, новые действия возвращают `ENGINE_CURSOR_UNREADABLE`. [Документация `/live`](https://1in8b.life/en/api/#a-life-lived-from-outside)

Экран текущего frontend также использует локальные фокус года, близких, перенос решения и избранное. Для вкладки трат доступны серверные методы ниже.

## Траты и вложения

Вкладка следует OpenAPI 0.5.0. Все три запроса используют существующую cookie гостя и один и тот же `sessionId`.

1. При открытии вкладки вызовите `GET /api/v1/sessions/{id}/finances`. `summary` содержит доходы, расходы, накопления и доступный остаток. `ledger` и `purchases` идут от новых к старым. Категории приходят в `categories` вместе с подписями, минимальным возрастом и ценой «от». В `relationships.actions` есть позиции для отображения на самой вкладке. `city` и `country` объединяются по `groupId: "moving"`.
2. При открытии окна категории вызовите `GET /api/v1/sessions/{id}/spending/{categoryId}`. Используйте `heading`, `description`, `confirmLabel` и `offers`. В модальном окне показывайте `availableBalance`, для процедур и внешности также соответствующее поле из `stats`. У выбранного предложения поля `price`, `yearlyCost`, `durationMonths`, `effects`, `location` и `balanceAfterPurchase` дают стоимость, содержание, длительность, эффект, место и прогноз остатка. При `purchasable: false` отключите подтверждение и покажите `unavailableReason`. Из `suggestedPetNames` можно выбрать случайную кличку на клиенте.
3. При покупке отправьте `POST /api/v1/sessions/{id}/purchases` с новым заголовком `Idempotency-Key` и JSON с `expectedVersion`, `categoryId`, `itemId` и кличкой `petName` для питомца. Цену и остаток в запрос не включайте. Примените полученную сессию, затем обновите вкладку. Повтор отправляйте с тем же ключом и телом. При `VERSION_CONFLICT` загрузите свежие данные. После перехода года или принятого решения обновляйте вкладку, если она открыта.

```json
{"expectedVersion":9,"categoryId":"pets","itemId":"hamster","petName":"Луна"}
```

`local` использует игровые рубли. Доходы и расходы за последние 12 игровых месяцев начисляются при переходе на следующий год жизни. Карманные деньги за первый год поступают на седьмой день рождения. Содержание приобретений начисляется со следующего игрового месяца. В сводку входит 1% игровых годовых на положительный остаток на начало года. Если содержание создаёт долг, новый доход сначала его покрывает. Курсы помечаются как завершённые на первой сохранённой границе года после окончания курса. Текущее место жительства берите из `finances.location`, а место рождения — из `character.birthplace`.

`1in8b` использует `PPP_USD`. Форматируйте как международные доллары по ППС. Поле `summary.netWorth` — чистая стоимость имущества. Для доступного остатка, расходов, накоплений и детализации используйте состояние «Нет данных» при `null`. Категория `provider` появляется, когда в сохранённом ответе есть предложения. Её позиции доступны для просмотра, а отправка покупки возвращает `409 SPENDING_READ_ONLY`. GET обоих маршрутов читает PostgreSQL и не обращается к поставщику.

Для ручной проверки создайте локальную жизнь через `POST /api/v1/sessions` по примеру выше. После ответа в мастерской продолжите через `advance` до семи лет. Запросите `/spending/pets`, затем купите хомяка с кличкой. Ожидаемый остаток меняется с 1 200 до 600 ₽. Повторите команду с тем же ключом и убедитесь, что в `/finances` одна покупка. Docker обслуживает запросы по адресу `http://127.0.0.1:8081`.

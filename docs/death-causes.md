# Причины смерти — OpenAPI 0.8.2

25.11.2026. Собственный пошаговый движок: персонаж и близкие. Frontend не изменён.

## Расчёт

При положительном здоровье `MortalityModel` определяет сам факт смерти по общей смертности UN WPP 2024 и игровому модификатору здоровья. Сохраняются двухмесячный шаг и единственный бросок смертности. Возрастной предел не добавлен. С 0.8.4 здоровье 0 завершает жизнь немедленно, в текущем месяце и без броска: [правила](life-rules-0.8.4.md). Причиной становится наиболее тяжёлый известный активный эпизод; без него — «Критическое ухудшение здоровья» без вымышленного диагноза. Старые идентификаторы модели и коды сохранены для декодеров, конкретное правило поясняется в `note`.

Только если смерть уже наступила, `DeathCauseModel` выбирает причину. Это отдельная, воспроизводимая модель `death-causes-1`: seed сохранения, ID человека и месяц смерти задают собственный поток случайности. Он не расходует случайность событий и не увеличивает вероятность умереть. Аура, близость и контакт не участвуют.

В базе загружена **общая смертность**, а не распределения причин смерти. Возрастные ограничения и веса причин ниже — **игровые допущения**, одинаковые для всех поддерживаемых стран. Новая статистика не импортировалась. Код и ответ явно содержат `basis: GAME_ASSUMPTION`; это не медицинский прогноз и не частоты причин из ООН.

| Код | Подпись | Условие игровой модели |
| --- | --- | --- |
| `PERINATAL_COMPLICATIONS` | Осложнения перинатального периода | Возраст до 1 месяца включительно; временная точность модели — месяцы |
| `CONGENITAL_CONDITION` | Осложнения врождённого заболевания | Младше года |
| `RESPIRATORY_INFECTION` | Тяжёлая пневмония | От одного месяца |
| `SEVERE_INFECTION` | Тяжёлая инфекция | Любой возраст |
| `ACCIDENT` | Смертельная травма при несчастном случае | От года; риск текущей работы учитывается только с 18 лет |
| `HEART_ATTACK` | Инфаркт миокарда | От 35 лет |
| `STROKE` | Инсульт | От 45 лет |
| `CANCER` | Онкологическое заболевание | От года |
| `ACUTE_DISEASE_COMPLICATIONS` | Осложнения текущего заболевания | Существующий активный эпизод `HEALTH_CONDITION` |
| `CHRONIC_DISEASE_COMPLICATIONS` | Осложнения хронического заболевания | Такой же эпизод с `chronic=true` |
| `INJURY_COMPLICATIONS` | Осложнения недавней травмы | Активная нехроническая `INJURY`, тяжесть ≥20, давность ≤12 месяцев |

Эти ограничения упрощают игровую генерацию; они не утверждают, что заболевания невозможны в другом возрасте в реальной жизни.

Вес медицинских причин зависит от здоровья. Для осложнений учтены тяжесть, актуальность эпизода и наблюдение специалистом; завершённые и будущие эпизоды исключены. Эти веса перераспределяют **уже наступившую** смерть между причинами. Наблюдение не отменяет результат общего расчёта смертности.

Существующие эпизоды здоровья пока не содержат точных диагнозов. Поэтому generic `HEALTH_CONDITION` не переименовывается в рак или болезнь сердца: при выборе осложнения возвращается исходный `conditionId`. Прочие причины могут описывать внезапный или ранее не диагностированный игровой случай, не создавая задним числом медицинскую историю. Подробная история заболеваний NPC пока отсутствует: у близких используются возраст и доступное здоровье, без заимствования болезней героя.

## Ответ и сохранение

Конкретная причина героя — `simulation.death.causeDetails`. Для умершего близкого — `simulation.family[].death.causeDetails`.

```json
{
  "elapsedMonths": 841,
  "age": 70,
  "cause": "UNSPECIFIED",
  "model": "UN_WPP_2024_QX",
  "note": "Смертность — по таблицам ООН. Конкретная причина выбрана игровой моделью, а не статистикой причин смерти.",
  "causeDetails": {
    "code": "HEART_ATTACK",
    "label": "Инфаркт миокарда",
    "model": "death-causes-1",
    "basis": "GAME_ASSUMPTION",
    "conditionId": null
  }
}
```

`cause: UNSPECIFIED` — устаревший совместимый маркер, который текущий frontend проверяет строго. Он сохранён, чтобы обновление backend не сломало завершение игры. **Конкретную причину нужно читать из `causeDetails`**. `model` на уровне смерти описывает общий риск, внутри `causeDetails` — модель выбора причины.

`elapsedMonths` всегда отсчитывается от рождения героя; `death.age` у близкого — возраст именно этого близкого. Причина и возраст сохраняются один раз, вместе со смертью. Причина включена в текст события летописи. Повтор запроса возвращает прежний результат; GET ничего не пересчитывает. Смерть героя по-прежнему завершает сессию (`COMPLETE`), смерть близкого — только его личную историю.

Сведения хранятся в существующем JSONB `life_session.simulation`: в `death` героя и `family[].death`. Новая SQL-миграция не требуется. Старые JSON без полей читаются; причина у уже умерших **не выдумывается задним числом**. У живого близкого `death=null`; у умершего из старого сохранения это поле также может быть `null`. Признаком смерти остаётся `alive=false`.

Изменение относится к собственному движку. Ответы внешнего `1in8b` и прежний демонстрационный `/advance` не переинтерпретируются. Проверки владельца, версии, идемпотентности и блокировка завершённых сессий прежние.

## Задание для frontend

Обновить типы и декодеры по OpenAPI 0.8.2, **не менять вёрстку, стили и расположение компонентов**:

1. В `SimulationDeath` добавить optional/nullable `causeDetails` со структурой из контракта. Прежние `cause` и `model` сохранить для совместимости.
2. В типе близкого добавить optional/nullable `death: SimulationDeath`.
3. В существующем выводе завершения жизни использовать `simulation.death.causeDetails.label`. В существующей информации об умершем близком — `person.death?.causeDetails?.label`. При отсутствии — «Причина не установлена»; не скрывать завершение жизни.
4. Не вычислять причины локально, не подставлять «старость» по возрасту и не использовать `UNSPECIFIED` как подпись. `conditionId` может отсутствовать по смыслу (`null`); это не ошибка.
5. Сохранить остановку таймера при `COMPLETE`. Смерть близкого не останавливает жизнь героя. При восстановлении использовать сохранённый ответ; событие летописи уже содержит причину, дублировать его не нужно.
6. Проверить новое завершение, смерть близкого, старую смерть без подробностей, обновление страницы, проверку типов, тесты и сборку.

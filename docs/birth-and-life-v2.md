## Поля карточки рождения

| Элемент | Источник |
|---|---|
| Достаток семьи / достаток | `birthFacts.wealth.value`, также `background.wealth`; квинтиль `birthDetails.familyIncomeQuintile` |
| Шанс родиться в стране | `birthFacts.worldBirthProbability.value × 100` процентов |
| Вероятность выбора страны в текущей игре | `birthFacts.selectionProbability.value`; это отдельная величина, не мировой шанс |
| Мама и папа | `birthDetails.mother/father`: возраст при рождении, occupation.label, alive; имена — `simulation.family` по role |
| Братья/сёстры | `birthDetails.siblings`: возраст/пол при рождении; имена/id — `simulation.family` |
| Жильё | `birthFacts.housing.value` / `background.housing` |
| Отношения в семье при рождении | `birthFacts.familyRelationships.value`; текущие — отдельная близость родственников |
| Вера семьи | `birthFacts.familyFaith.value` |
| Язык в семье | `birthFacts.familyLanguage.value` — код CLDR; отображать локализованным названием, сохранив код при отсутствии перевода |
| Религии страны | `birthFacts.countryReligions[]`: code и percent (уже проценты, не умножать на 100), оценки 2020 года |
| ВВП на душу населения | `birthFacts.gdpPerCapita.value`, unit=USD_CURRENT, year=2023 |
| Валюта страны | `birthFacts.currency`: RUB, JPY или INR |
| Ожидаемая продолжительность жизни | `birthFacts.lifeExpectancy.value` лет, прогноз на 2026 год |
| Смертность до 5 лет | `birthFacts.underFiveMortality.value × 100` процентов, прогноз на 2026 год |

`worldBirthProbability` — шанс страны рождения, а не вероятность всей комбинации пола, имени и семьи. `selectionProbability=1` при явном выборе страны; иначе нормируется среди трёх доступных стран. Валюта страны не заменяет `finances.currency`: существующий игровой бюджет local пока в RUB. ВВП указан в текущих USD, не в рублях и не в международных долларах по ППС.

Религии: Christians — христианство; Muslims — ислам; Unaffiliated — без религиозной принадлежности; Buddhists — буддизм; Hindus — индуизм; Jews — иудаизм; Other religions — другие религии. Не добавлять значения отсутствующих групп. Языковые доли CLDR могут пересекаться: люди владеют несколькими языками.

## Поведение движка

Каталог childhood-2 содержит 97 авторских ситуаций с возрастными условиями, живыми участниками, навыками, флагами, близостью и отложенными последствиями. Один шаблон не повторяется в течение игрового года; обычный интервал повторения — не менее двух лет. Предпочтение отдаётся ещё не использованным ситуациям. Для некоторых повторяемых взрослых ситуаций есть варианты текста. Это конечный каталог: на длинной жизни тематические повторы всё ещё возможны, особенно после детства. Полная система карьеры, болезней и взрослых сюжетов остаётся отдельным этапом.

С 0.8.4 начиная с 38-го месяца решения появляются вероятностно, в зависимости от здоровья, счастья и близости с родными. Не более двух вопросов за год летописи, интервал не менее четырёх месяцев; обязательного минимума нет. До трёх лет решений нет. Отложенные последствия продолжаются автоматически. Выбор увлечения не обязан менять моральную ауру: её меняют поступки вроде честности, заботы, обмана и грубости. Близость и доверие меняются у конкретного выбранного родственника, а общий показатель отношений сохраняет бонусы покупок. История возвращает фактические дельты с учётом пределов шкал. Подробности — [life-rules-0.8.4.md](life-rules-0.8.4.md).

Старые childhood-1 продолжаются под childhood-2 при следующем действии. Идентификаторы прежних решений и вариантов сохранены. Seed, родственники и уже прожитая история не генерируются заново, повторы из прошлого не удаляются. Отсутствующие страновые факты добавляются при продолжении; неизвестные старые семейные сведения остаются null. Источник первоначального рождения сохранён в `statisticsRelease`; актуальная модель раскрывается в `engineVersion`, `birthFacts` и `assumptions`. У 1in8b и ручных анкет новые сведения могут быть null, поведение `/advance` не меняется.

## Смертность и её границы

Данные ООН WPP 2024: qx для каждого пола, возраста 0–100 и года 2024–2100, medium projection, по трём странам. Риск двухмесячного интервала:

`q_step = 1 - (1 - qx)^(R × 2/12)`.

`R = exp((70 - health)/100)` — явно игровое приближение, нейтральное при health=70. После покупок и решений используется новое здоровье. Аура напрямую не влияет на риск смерти. Риск пересчитывается только при продвижении времени, не при ответе на выбор или повторе HTTP-запроса. Дата смерти при рождении не назначается.

Для возраста 100+ используется интенсивность mx открытого интервала, а не qx=1, чтобы не создавать искусственную смерть в 100 лет. После 2100 года применяется таблица 2100 года; до 2024 — таблица 2024 года. Внутри возрастного года интенсивность считается постоянной; для первого года это приближение без отдельного неонатального распределения. Попадание смерти в первый месяц двухмесячного слота — дискретизация времени, не точная календарная дата.

Пока используется страна рождения; изменение профиля смертности после переезда в неподдерживаемую страну не моделируется. Родственники проверяются по собственным возрасту и полу с нейтральным R=1. После смерти NPC исключается из новых взаимодействий, его возраст фиксируется, событие утраты снижает счастье. После смерти героя жизнь становится COMPLETE, будущая очередь очищается, деньги начисляются только до достигнутого месяца.

В исходной версии причина возвращалась `UNSPECIFIED`. С OpenAPI 0.8.2 добавлена отдельная игровая атрибуция `death.causeDetails` с учётом возраста и эпизодов здоровья взрослой модели — [death-causes.md](death-causes.md). Прежнее поле сохранено для совместимости. Статистики отдельных причин и медицинской модели конкурирующих рисков пока нет; конкретная причина явно помечается игровым допущением. Формула интервалов проверена на точное восстановление годового qx при R=1; это не подтверждение калибровки всей игровой популяции после применения игровых модификаторов.

## Данные и запуск

Источники, лицензии и воспроизведение импорта: `docs/statistical-sources.md`. Новая Flyway V5 создаёт только таблицы reference_release, country_birth_reference, mortality_rate. Существующие сохранения и старые миграции не переписываются.

```powershell
docker compose build backend
docker compose run --rm --no-deps backend --spring.main.web-application-type=none --life.statistics.import=true
docker compose up -d --no-deps --wait backend
.\scripts\Test-LocalLife.ps1
```

Импорт проверяет SHA-256, идентификатор неизменяемого релиза, диапазоны, полноту и уникальность. Повтор идемпотентен. Тесты и игра не обращаются к внешним источникам. На уже обновлённом Docker достаточно создать новую local-жизнь; старую можно продолжить, но её исторические повторы останутся.

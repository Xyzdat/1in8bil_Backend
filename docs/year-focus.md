# Фокус года — контракт 0.10.0

Модель `year-focus-1`, 27.11.2026. Только новые жизни собственного движка. Frontend не изменён. Старые сохранения, демонстрационный `/advance` и `1in8b` продолжают свои прежние правила.

## Выбор и сохранение

Данные приходят вместе с Session в `simulation.yearlyFocus`. Для старой жизни поле равно `null`: создавать новый фокус на frontend или начислять ему эффекты не нужно. У внешнего/демонстрационного сценария сама `simulation` также может быть `null`.

Новый маршрут:

```http
PATCH /api/v1/sessions/{sessionId}/focus
Content-Type: application/json
Idempotency-Key: <новый UUID команды>
Cookie: <прежняя гостевая cookie>

{"expectedVersion": 12, "focusId": "learning"}
```

Ответ — полный Session с новой `version`. Работают проверка владельца, блокировка записи и прежняя защита идемпотентности. Повтор идентичного ключа возвращает актуальную сессию без повторного действия. Тот же ключ с другим содержимым — `409 IDEMPOTENCY_CONFLICT`; устаревшая версия — `409 VERSION_CONFLICT`. Два одновременных разных выбора с одной версией дают один успех и один конфликт.

Фокус можно менять в течение года, на паузе и при открытом вопросе. Смена не двигает время, не применяет эффекты, не списывает деньги и не заменяет уже предложенный вопрос или очередь последствий. Выбор сохраняется при восстановлении и **остаётся выбранным после дня рождения**, пока игрок его не изменит. «Фокус года» обозначает текущий приоритет; ежегодное подтверждение не требуется. Работа в 65 лет сменяется балансом.

Старые жизни без `simulation.focus` не подключаются автоматически, PATCH возвращает `409 FOCUS_UNSUPPORTED`. Для новой жизни фокус изначально `balanced`. Содержательные направления доступны с 3 лет, `work` — с 18 до 64. Другой возраст — `409 FOCUS_UNAVAILABLE`. Неизвестный ID — `400 INVALID_FOCUS`. Завершённая жизнь — `409 SESSION_COMPLETE`; если активное сохранение имеет здоровье 0, общее правило сначала завершает его и возвращает COMPLETE без выбора фокуса.

## Что получает frontend

`simulation.yearlyFocus` содержит:

- `modelVersion`, `year` (возрастной год, не календарный), `selectedId`, `changedMonth`, `canChange`.
- `context`: возрастная стадия или известная текущая учёба/работа. Школьный возраст 6–17 здесь игровое обобщение; номер класса и конкретная школа не выдумываются. Страну и город брать из прежних полей персонажа/текущего проживания.
- `options`: каталог вариантов с `id`, `title`, `description`, `available`, `reason`, `effects` и `matchingEventWeightMultiplier`.
- `lastApplied`: фактические разности от фокуса за последний обработанный интервал: `focusId`, `month`, `stats`, `skills`, `closeness`. Пустые карты допустимы. После смены это может быть ещё запись прежнего направления — проверять `focusId`. Это не общий результат шага и не команда повторного начисления.

Названия и доступность брать из ответа. Например, у ребёнка `friends` называется «Друзья и игры», у взрослого — «Друзья и общение». `home` — «Помощь по дому»/«Семья и дом». Недоступный вариант имеет `available=false` и причину.

`options[].effects.periodMonths=12`. `stats` — темпы прямых изменений характеристик, `skills` — навыков по ключам `simulation.skills`, `closeness` — близости по ID уже существующих доступных для общения людей. Положительный знак означает улучшение, отрицательный — ухудшение. Не прибавлять эти числа к состоянию на frontend.

| ID | Название | Прямые игровые темпы за 12 месяцев |
| --- | --- | --- |
| balanced | Баланс | Нет дополнительного изменения |
| learning | Учёба | Интеллект +3, счастье −1, навык learning +3 |
| friends | Друзья и игры / общение | Отношения +3, счастье +1, близость с друзьями +2 |
| home | Помощь по дому / семья и дом | Отношения +2, интеллект −1, ответственность +2, близость с доступными родными +2 |
| health | Физические упражнения | Здоровье +3 |
| creativity | Увлечения | Счастье +2, creative_practice +3 |
| rest | Отдых | Здоровье +2, интеллект −1 |
| work | Работа | Интеллект +1, счастье −1, professional_practice +3 |

`learning`, `creative_practice`, `professional_practice` — общие навыки практики, а не диплом, известная профессия или автоматически приобретённое хобби. Доступные имена людей нужно сопоставлять по ID. Неизвестные родственники/друзья не создаются ради бонуса.

## Как начисляются эффекты

Темп действует пропорционально реально прожитому времени. Пример: два месяца учёбы накапливают 6/12 пункта интеллекта; после четырёх месяцев применяется +1, остаток сохраняется. Отрицательные значения округляются к нулю симметрично положительным. Дробные остатки не исчезают при смене, сохранении и восстановлении. Смена в середине года влияет только на следующие месяцы.

Начисления выполняются один раз за прожитый интервал `/step`, после проверки выживания. Ответ на решение, покупка, редактирование, GET и смена фокуса их не запускают. Шкалы характеристик, близости и навыков ограничены 0–100; аура напрямую фокусом не меняется. Состояние не оживляется при здоровье 0. Умершим людям и людям со статусом NO_CONTACT бонус близости не назначается. Взрослый семейный/дружеский фокус отмечает обычное общение с доступными людьми и поддерживает связь, но явный разрыв не отменяет.

Это дополнительное влияние фокуса. События и решения продолжают отдельно менять характеристики, поэтому указанные годовые темпы не гарантируют итоговый рост на ту же величину. Новые отдельные события за каждую дробную выплату в летопись не добавляются; фактическая часть фокуса доступна в `lastApplied` и итоговом состоянии.

## Вероятности и цепочки

У подходящих доступных событий вес умножается на 3, у остальных остаётся прежним. Это **не означает утроение итоговой вероятности**: после изменения весов распределение нормализуется по всему подходящему набору.

- В детстве используются явно перечисленные ID шаблонов. Увлечения повышают вес начала рисования и творческих занятий, учёба — задач/чтения, дом — совместных дел с семьёй, здоровье — движения. Применяется прежняя фильтрация по возрасту, участникам, навыкам, флагам и повторам.
- Во взрослом возрасте повышаются веса начала доступных сюжетов нужного направления: учёба → EDUCATION; работа → CAREER/BUSINESS; семья → FAMILY; друзья → SOCIAL; здоровье/отдых → HEALTH. Увлечения поддерживают соответствующие повседневные занятия и подходящий поздний сюжет `later-life`; отдельной новой системы взрослых хобби эта задача не добавляет.
- Для взрослой повседневности фокус влияет на выбор подходящего занятия с защитой от повторов. Для баланса и старых жизней сохранён прежний алгоритм выбора самого давнего занятия.
- Уже начатые цепочки, назначенные сроки, последствия решений и их условия не отменяются и не ускоряются фокусом. Принятые решения по-прежнему определяют продолжения.
- Фокус не гарантирует событие, положительный исход, работу, брак, ребёнка, доход или выздоровление. Вероятность предложения вопроса по-прежнему зависит от текущих проблем; максимум два вопроса за год и интервалы между ними сохраняются. Косвенно она может измениться позже, если здоровье/счастье/отношения изменились.

Все веса, темпы и возрастные пороги — явные игровые правила, не статистика стран.

## Хранение и совместимость

Сервер хранит версию, выбор, месяцы выбора/начисления, дробные остатки, историю смен и последнюю выплату в необязательном `simulation.focus`. В одном игровом месяце остаётся последний эффективный выбор, чтобы переключения на паузе не раздували историю. Поле не раскрывает будущую очередь событий.

Схема таблиц не меняется: используется существующий JSONB. Flyway-миграция не нужна, старые миграции не редактируются. Старые JSON команд без focusId читаются как прежде. Новые жизни с балансом сохраняют прежние игровые вероятности и не получают дополнительных прибавок. Статистика, импорт, зарплатные модели, токены и квоты внешнего API не затрагиваются.

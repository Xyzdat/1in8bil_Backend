# Настройка персонажа и семьи — OpenAPI 0.9.0

26.11.2026. Frontend не изменён. Используется прежний метод:

`PATCH /api/v1/sessions/{id}/character`

Нужны cookie владельца, заголовок `Idempotency-Key` (UUID) и актуальная `expectedVersion`. Ответ — полный `Session`. ID жизни не меняется. Запросы к 1in8b для этой функции не выполняются.

## Когда разрешено

Для собственного движка имя и основные характеристики редактируются существующим методом. Новые поля рождения и семьи доступны **только при настройке созданного новорождённого, до первого `/step`**, как согласовано с владельцем проекта. Проверка: `provider=local`, `simulation != null`, `simulation.elapsedMonths=0`, `state.status=ACTIVE`. Одного `state.age=0` недостаточно: после двух месяцев возраст ещё 0, а настройка уже заблокирована.

После начала жизни `sex`, `birthYear`, `birthplace`, `family` возвращают `409 BIRTH_CONFIGURATION_LOCKED`. Это не переезд и не изменение семьи задним числом. Для старого демонстрационного local без `simulation` эти блоки дают `409 BIRTH_CUSTOMIZATION_UNSUPPORTED`; имя и характеристики по-прежнему доступны. Для `1in8b` сохраняются прежние ограничения: можно менять отображаемое имя и внешность приложения, остальные новые поля дают `409 CHARACTER_FIELDS_READ_ONLY`.

## Пример запроса

```json
{
  "expectedVersion": 1,
  "changes": {
    "name": "Александра",
    "sex": "FEMALE",
    "birthYear": 2026,
    "stats": {
      "health": 85,
      "happiness": 75,
      "intelligence": 70,
      "relationships": 80,
      "appearance": 65,
      "aura": 10
    },
    "birthplace": {
      "countryCode": "JP",
      "region": "Кансай",
      "city": "Кобе",
      "placeType": "URBAN"
    },
    "family": {
      "incomeQuintile": 3,
      "housing": "Съёмная квартира",
      "relationships": "Тёплые отношения",
      "religion": "Буддизм",
      "language": "ja",
      "members": [
        {"role":"mother","name":"Анна","ageAtBirth":30,"occupation":"Врач","closeness":85,"trust":80},
        {"role":"father","name":"Алексей","ageAtBirth":32,"occupation":"Инженер","closeness":80,"trust":75},
        {"role":"sister","name":"Мария","ageAtBirth":4,"closeness":70,"trust":65}
      ]
    }
  }
}
```

Все поля в `changes` необязательны, но нужно хотя бы одно значение. Пропуск/null означает «оставить прежнее». Пустые `city` и `region` очищают эти поля. Страна задаётся **двухбуквенным ISO2** (`JP`, `RU`, `IN` и т. д.), в отличие от `countryIso3` при генерации. Поддерживаются те же 36 стран. При смене страны старые город и регион удаляются, если новые не переданы. Название страны, валюта, ВВП, вероятности, продолжительность жизни и справочники религий/языков берутся из PostgreSQL, их нельзя прислать вместо официальных данных. Регион и город — введённые пользователем подписи, не проверенные координаты.

`sex` принимает `FEMALE`/`MALE`; в ответе `character.gender` остаётся «Женщина»/«Мужчина», а `birthFacts.sex` содержит код. Год рождения доступен в том же диапазоне 2023–2026, что и при генерации. Изменение года не меняет годы опубликованных статистических показателей. При настройке используется текущий релиз `birth-context-2026-v2`; seed, ID и месяц жизни сохраняются. Модель смертности в дальнейшем использует выбранные страну, пол и год.

Характеристики — целые 0–100, аура — −100…100. Общие `stats.relationships` и индивидуальная близость родственников — разные значения: редактирование одного не присваивает его всем родственникам. Здоровье 0 по действующему правилу завершает собственную пошаговую жизнь в этом же ответе; клиент должен обработать `COMPLETE`.

## Семья и устойчивые ID

`family.members` — **полная замена** списка известных живых родителей и братьев/сестёр на момент рождения. Если нужно изменить одного человека, отправьте весь текущий список с нужной правкой. Если `members` не передан, список сохраняется; `members: []` означает семью без указанных родственников. Удаление родственника здесь означает отсутствие в исходной семье, а не событие смерти.

У существующего родственника передавайте `id` из `simulation.family[]`. ID повторяться не должны и должны принадлежать этой семье. У нового родственника `id` пропускается: сервер создаст устойчивый `relative-...`. После ответа сохраните выданные ID. Повтор того же запроса с тем же `Idempotency-Key` не создаст ещё одних родственников. Одинаковые имена разрешены, ключом служит ID.

Обязательные поля каждого элемента: `role` (`mother`, `father`, `brother`, `sister`), `name`, `ageAtBirth`. Это возраст родственника **при рождении героя**, не текущий возраст. Пол родственника определяется ролью. `occupation` необязателен; пропуск сохраняет существующую профессию, пустая строка очищает её. Близость и доверие — 0–100; при пропуске сохраняются старые значения, у нового родственника по умолчанию 65 и 60.

Игровые ограничения: максимум два родителя и десять братьев/сестёр, возраст 0–80, родителям минимум 18; каждый родитель минимум на 16 лет старше старшего указанного брата/сестры. Это ограничения текущей модели, не правила усыновления или утверждение о реальных семьях. Поддерживаются один родитель, две мамы, два папы, оба родителя и отсутствие указанных родителей. Для одного/нуля родителей старое перечисление `birthDetails.familyType` возвращает `null`; полную семью всегда читать из `simulation.family`. Поля `birthDetails.mother/father` содержат первого родителя соответствующей роли и не заменяют полный список.

При замене семьи, если `stats.relationships` не указан явно, общий показатель становится средним значением близости (0 при пустом списке). Описание отношений выводится из близости, если не передано явно. Карточка рождения, возраст/профессия родителей, сведения о братьях/сёстрах и исходная запись «Рождение» обновляются согласованно. Другие записи, покупки, история бюджета и подборка решений не переписываются; настройка не становится игровым решением для слайд-шоу.

`incomeQuintile` — достаток от 1 до 5; он меняет описание семьи, но **не зачисляет деньги**, не превращает ВВП в зарплату и не заменяет бюджет. Жильё, вера, язык и описание атмосферы семьи — строки до 120 символов. Введённые значения возвращаются с `basis=GAME_ASSUMPTION`, `source=user-customization` и пояснением; они не выдаются за статистическую выборку. При смене страны вера и язык семьи сохраняются с такой отметкой, а справочники новой страны обновляются. Люди, их имена и характеристики не генерируются заново только из-за смены страны.

## Ошибки и сохранение

- `400 INVALID_COUNTRY` — неподдерживаемая страна; `400 INVALID_FAMILY` — повторный/чужой ID, слишком много родителей или противоречивые возраста.
- `400 INVALID_REQUEST` и ошибки валидации — пустое изменение, неизвестное поле, некорректный диапазон/тип.
- `409 VERSION_CONFLICT` — перечитать сессию, показать актуальные данные; не повторять старую правку вслепую.
- `409 IDEMPOTENCY_CONFLICT` — тот же ключ применён к другому содержимому. Для нового действия нужен новый UUID.
- `401` без владельца, `404` для чужого/отсутствующего сохранения. При отклонённой команде частичные правки не сохраняются.

Flyway **V8** добавляет nullable `life_session.character_customization jsonb`. Исходный `setup` и исходный запрос рождения сохраняются отдельно от пользовательской настройки. Поэтому повтор первоначального создания возвращает ту же отредактированную жизнь, даже если страна и год поменялись. Другие сохранения миграция не переписывает.

## Что передать чату frontend

Подключи расширенный `PATCH /api/v1/sessions/{id}/character` по OpenAPI 0.9.0 и этому документу. Вёрстку и стили не меняй. Расширь тип запроса и подключи существующие поля редактора; если для новых данных нет элементов управления, перечисли их отдельно, не добавляй интерфейс без согласования. Страну, пол, год рождения и семью разрешай редактировать только для ACTIVE local с `simulation.elapsedMonths === 0`; одного возраста 0 недостаточно. Передавай семейный список целиком с серверными ID, а новым родственникам ID не назначай. Отправляй `expectedVersion` и `Idempotency-Key`, после PATCH заменяй весь Session и обновляй финансы/данные места. Обрабатывай перечисленные ошибки и `COMPLETE`. Кнопка «Начать жизнь» продолжает этот же id, повторный POST создания не нужен. Структура ответа прежняя; `familyType=null`, одинаковые имена и несколько родителей одной роли допустимы.

До успешного сохранения редактора и нажатия «Начать жизнь» не запускай `/step`: первый шаг закрывает настройки рождения.

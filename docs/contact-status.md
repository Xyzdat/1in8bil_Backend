# Связь с близкими — OpenAPI 0.8.1

25.11.2026. Дополнение к взрослому движку `adult-1`. Frontend не изменён.

## Правила

У каждого живого известного взрослой модели человека хранится отдельная связь с героем:

| Код API | Подпись | Значение |
| --- | --- | --- |
| `IN_TOUCH` | Общаемся | Недавний контакт или поддерживаемое общение в семье/текущей паре |
| `RARE_CONTACT` | Редко общаемся | Не было учтённого контакта 6 игровых месяцев |
| `NO_CONTACT` | Связь прервана | Нет контакта 24 месяца либо принято явное решение прекратить общение |

Это игровые правила. Близость и доверие могут оставаться высокими после потери связи. Развод или расставание сами по себе не означают `NO_CONTACT`.

Обычный разговор возвращает редкое общение в `IN_TOUCH`. Для уже прерванной связи нужен отдельный сюжет **«Вернуться к общению?»**: написать → дождаться ответа → последующий разговор. Ответ может быть отрицательным. Восстановление связи не восстанавливает автоматически брак или романтические отношения.

В семейном конфликте появился отдельный вариант **«Расстаться и прекратить общение»**. В сюжете контакта можно также прекратить общение или оставить всё как есть. Используются существующие `/step` и `/decisions/{decisionId}/answers`; новых HTTP-маршрутов нет. Список вариантов приходит от сервера, их число не фиксировано.

После `NO_CONTACT` человек остаётся в сохранении и семейных связях. Обычные разговоры и новые совместные сюжеты с ним не выбираются; ожидающие совместные этапы отменяются. Возобновить контакт случайной повседневной сценой нельзя. При этом финансовые обязательства перед детьми, независимая жизнь NPC, уже наступившая беременность, наследство и память об умерших не удаляются. Получить известие о человеке не означает лично с ним пообщаться.

Текущая пара и зависимые несовершеннолетние дети по игровой модели поддерживают контакт между отдельными записями летописи. Родители и братья/сёстры также поддерживают его, пока герой живёт в `FAMILY_HOME`. Это упрощение текущей модели домохозяйства. Явно прерванная связь не восстанавливается даже этим правилом.

Смерть не обозначается как «Связь прервана»: для `alive=false` публичный `contact=null`, а прежняя запись контакта сохраняется внутри истории состояния.

## Ответ API

Дополнительное поле `simulation.family[].contact`:

```json
{
  "status": "RARE_CONTACT",
  "trackedSinceMonth": 216,
  "lastContactMonth": 240,
  "statusSinceMonth": 246,
  "reason": "TIME_APART"
}
```

Все месяцы отсчитываются от рождения героя. Это не календарные даты и не возраст родственника. `lastContactMonth=null` означает, что точная дата не известна. `trackedSinceMonth` — начало наблюдения; `statusSinceMonth` — начало текущего статуса.

Поле optional/nullable для совместимости. До взрослого движка и до первого действия после обновления старого сохранения оно может отсутствовать или быть `null`. Frontend не должен считать это разрывом связи.

`reason`: `INITIALIZED`, `INTERACTION`, `HOUSEHOLD`, `TIME_APART`, `PLAYER_CHOICE`, `RECONNECTED`. При первом включении наблюдения старым живым NPC задаётся исходное `IN_TOUCH`, но дата прошлой встречи не выдумывается: `lastContactMonth=null`, `reason=INITIALIZED`. Отсчёт молчания начинается с текущего игрового месяца.

## Хранение и совместимость

Записи сохраняются в `life_session.adult_state.contacts`, ключ — неизменяемый ID человека. JSONB-колонка уже существует, структура таблиц не меняется, новая SQL-миграция не требуется. Отсутствующая карта старого JSON читается как пустая и заполняется при очередном действии. GET не изменяет версии и сохранения. Покупки сохраняют карту контактов. Действуют прежние проверки владельца, версии и идемпотентности.

Новая статистика не загружалась; внешние сервисы не вызываются. `1in8b`, старые `/advance`-сессии и детская модель не получают вымышленных контактов.

## Задание для frontend без изменения вёрстки

1. Добавить optional/nullable `contact` в тип и декодер `SimulationFamilyMember` по `docs/openapi.yaml` 0.8.1.
2. В существующей карточке близкого показать русскую подпись `status`. При `null` не выдумывать значение; при `alive=false` приоритет имеет информация о смерти.
3. Не вычислять контакт из близости, роли `partner` или брачного статуса. Не удалять людей с `NO_CONTACT`; группировку семьи/друзей сохранять.
4. Использовать прежние динамические решения и обновлять полный Session после ответа. Локально статус не переключать, ожидаемого ответа не считать согласием.
5. Проверить старое сохранение без поля, редкое общение, явный разрыв, отказ/успех восстановления, обновление страницы и умершего NPC. Стили и структуру экранов не менять.
